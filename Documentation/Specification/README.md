# Specification/

Specs de travail définissant les **besoins** du projet.

## Objet
Décrire *quoi* faire et *pourquoi*, indépendamment de l'implémentation. Ces documents servent de référence pour découper les lots de travail (`../lot/`).

## Contenu attendu
- Vision et concept du jeu (genre, boucle de gameplay, objectif joueur).
- Besoins fonctionnels (mécaniques de plateforme, mécaniques de puzzle, contrôles, niveaux).
- Besoins non-fonctionnels (cible plateforme Windows/DirectX, performance, résolution, entrées clavier/manette).
- Contraintes techniques (C++, DirectX, from scratch — pas de moteur tiers).

## Convention
- Un fichier `.md` par thème de spec (ex. `gameplay.md`, `controles.md`, `rendu.md`).
- Chaque spec est numérotée / identifiable pour être référencée depuis les lots.
